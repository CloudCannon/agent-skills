# Page Building (Eleventy)

Read [../page-building.md](../page-building.md) first. This file covers only the Eleventy differences: block includes, the dispatcher and the page files. Which path the site takes decides the array shape — see [overview.md § Which path the site takes](../../cloudcannon-visual-editing/eleventy/overview.md#which-path-the-site-takes).

## The shape

| Piece               | Liquid path — component array                                                                                                                                                                                  | Nunjucks path — template array                                                                                                                                                              |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Content             | `content_blocks:` array in the page file's front matter, each item with `_type`                                                                                                                                | Same                                                                                                                                                                                        |
| Blocks              | One Liquid include per block type; `_type` is its path under the includes directory (`components/hero`)                                                                                                        | One Nunjucks include per block type, named after its `_type`                                                                                                                                |
| Dispatcher          | A `for` loop in the layout, rendering each block with `includeWith` — [Page builder blocks in Eleventy](../../cloudcannon-visual-editing/eleventy/visual-editing-reference.md#page-builder-blocks-in-eleventy) | A `for` loop in the layout, plus one `<template data-id>` blueprint per block type — [Nunjucks sites](../../cloudcannon-visual-editing/eleventy/visual-editing-reference.md#nunjucks-sites) |
| Editor re-rendering | Each block re-renders from its own data; `data-component` is the include path, with no registration                                                                                                            | None — blocks are wired with primitive regions, and markup outside them updates after a rebuild                                                                                             |
| Add-block menu      | `_structures.content_blocks`                                                                                                                                                                                   | Same                                                                                                                                                                                        |

## Steps

1. **Create** an include per block type under the includes directory, following the site's existing include layout (`components/hero.liquid`, `blocks/hero.njk`).
   - Liquid path: the include renders only from the block's own data — see [The include's data is the `data-prop` value](../../cloudcannon-visual-editing/eleventy/visual-editing-reference.md#the-includes-data-is-the-data-prop-value).
   - Nunjucks path: make every visible part of the block a region, with no `{% if %}` around optional parts — see [Nunjucks sites](../../cloudcannon-visual-editing/eleventy/visual-editing-reference.md#nunjucks-sites).
2. **Add** the dispatcher to every layout that renders page-builder pages, following the section the table links for the site's path. Write the region attributes now, along with the loop — the census gate covers existing page templates, not the dispatcher and block includes written here ([visual-editing.md § Section census](../../cloudcannon-visual-editing/visual-editing.md#section-census)).
3. **Move** each page's content into `content_blocks` in its page file — `index.md` in the input directory for the home page, `about.md` for `/about/`. Set its `layout` to a layout with the dispatcher.
4. **Write** `_structures.content_blocks` with one value per block type, `_type` set to the value the dispatcher uses — see [structures.md](../../cloudcannon-configuration/structures.md).
5. **Point** the `pages` collection at the page files, excluding folders that have their own collection and the includes and data directories — see [cloudcannon-configuration/eleventy/overview.md](../../cloudcannon-configuration/eleventy/overview.md). Give it a `url` that matches the built path — see [collection-urls.md](../../cloudcannon-configuration/eleventy/collection-urls.md).
6. **Build** and compare against the parity baseline.

## Common mistakes

| Excuse                                                                          | Reality                                                                                                                                                                                                                                         |
| ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| "I'll call the home page `home.md`"                                             | Eleventy builds `home.md` to `/home/`. The home page is `index.md` (or `index.njk`, `index.liquid`, `index.html`) in the input directory.                                                                                                       |
| "I'll make a `homepage` collection"                                             | Use one `pages` collection — see [../audit.md § Census table](../audit.md#census-table).                                                                                                                                                        |
| "`_type: hero` is enough" (Liquid path)                                         | `_type` is the full include path — `components/hero` for `_includes/components/hero.liquid` — see [Component names are include paths](../../cloudcannon-visual-editing/eleventy/visual-editing-reference.md#component-names-are-include-paths). |
| "The block include can read `page`, `title` or the loop variable" (Liquid path) | It works in the build and is `undefined` in the editor. Pass what the block needs in its own data.                                                                                                                                              |
| "The dispatcher only needs to be in one layout"                                 | Every layout that renders `content_blocks` needs it, or the pages on the other layout lose their blocks in the editor.                                                                                                                          |
| "Each block gets a unique `data-id`" (Nunjucks path)                            | `data-id` also picks the blueprint, so a unique id breaks adding blocks. Use the block type — see [Nunjucks sites](../../cloudcannon-visual-editing/eleventy/visual-editing-reference.md#nunjucks-sites).                                       |
| "I'll convert the Nunjucks templates to Liquid for components"                  | **Ask the user** first — see [overview.md § Which path the site takes](../../cloudcannon-visual-editing/eleventy/overview.md#which-path-the-site-takes).                                                                                        |
| "The block can render `{{ content }}`"                                          | The page body isn't part of the block's data. A block renders only its own front matter.                                                                                                                                                        |
