# Visual editing troubleshooting (Hugo)

Hugo-specific symptoms. Check the generic table in [../troubleshooting.md](../troubleshooting.md) first; the patterns behind these fixes are in [visual-editing-reference.md](visual-editing-reference.md).

Set `params.editable_regions.verbose: true` while debugging — the renderer then logs to the browser console inside the editor.

## Build

| Symptom                                                                               | Cause                                                                   | Fix                                                                                                                                                      |
| ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `editable-regions: no renderer WASM at … the resolved version … has no release asset` | The module is pinned to a commit or branch, which has no GitHub release | `hugo mod get github.com/CloudCannon/editable-regions@v0.0.21`. `_version` or `wasm_url` in `params.editable_regions` are for self-hosted renderers only |
| The build fails on a template function unrelated to editable regions                  | The site's Hugo is older than the target and uses a removed API         | Upgrade and fix the site first — see [visual-editing.md § Upgrading Hugo first](visual-editing.md#upgrading-hugo-first)                                  |
| Hugo reports it can't find the `github.com/CloudCannon/editable-regions` module       | The site isn't a module project, or `hugo mod get` wasn't run           | `hugo mod init <path>`, then `hugo mod get …@v0.0.21`                                                                                                    |
| `git status` shows `assets/jsconfig.json` with absolute paths                         | Hugo generates it for the module's `js.Build`                           | Gitignore it                                                                                                                                             |

## In the editor

| Symptom                                                                     | Cause                                                                                                                               | Fix                                                                                                                                                                                          |
| --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `No Hugo partial found for component "<name>"`                              | `data-component` names no bundled partial — a typo, a missing `partials/` prefix directory, or markup that lives in a page template | Match the name to a file under `layouts/partials/`. Extract page-template markup into a partial → [What the editor can re-render](visual-editing-reference.md#what-the-editor-can-re-render) |
| `Failed to render Hugo component "<name>": …`                               | The partial errored in the editor's Hugo — usually a call to the asset pipeline, `.Content`, or a file the bundle doesn't have      | Guard it with `{{ if not site.Params.ENV_CLIENT }}`, or give the editor a replacement with `templates_overrides` → [`ENV_CLIENT` in Hugo](visual-editing-reference.md#env_client-in-hugo)    |
| A component re-renders with its images missing                              | `resources.Get` returns nil in the editor                                                                                           | Guard the pipeline with `site.Params.ENV_CLIENT` and serve the plain path → [`ENV_CLIENT` in Hugo](visual-editing-reference.md#env_client-in-hugo)                                           |
| A component re-renders with its body text gone                              | The partial renders `.Content`, which is empty in the editor                                                                        | Move the body to a primitive `@content` region in the page template → [What the editor's Hugo has](visual-editing-reference.md#what-the-editors-hugo-has)                                    |
| A shared header or footer renders empty after an edit                       | It reads `hugo.Data.<name>` (`site.Data` on Hugo < 0.156) and `<name>` isn't in `data_config`                                       | Add the `data_config` entry → [Data files and `@data`](visual-editing-reference.md#data-files-and-data)                                                                                      |
| A theme or module partial is missing in the editor but renders in the build | It comes from the module cache, which the bundle can't see                                                                          | `hugo mod vendor` → [Themes, modules and vendoring](visual-editing-reference.md#themes-modules-and-vendoring)                                                                                |
| Bold or italic text prints as `**asterisks**` after a save and rebuild      | A `text`/`block` region saves markdown into a field the template renders raw                                                        | Add `\| markdownify`, or make the region `data-type="span"` → [Text regions and markdown in Hugo](visual-editing-reference.md#text-regions-and-markdown-in-hugo)                             |
| A layout shifts, or a button loses its box, once regions are added          | The `array-item` wrapper changed the flex/grid context of the component root                                                        | Give the component root its own `display` → [Wrapper elements around partials](visual-editing-reference.md#wrapper-elements-around-partials)                                                 |
| An empty array has nowhere to add a first item                              | The container is inside `{{ with .items }}`, so it isn't rendered                                                                   | `{{ if or .items site.Params.ENV_CLIENT }}` → [`ENV_CLIENT` in Hugo](visual-editing-reference.md#env_client-in-hugo)                                                                         |
