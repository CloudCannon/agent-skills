# Visual editing troubleshooting (Eleventy)

Eleventy-specific symptoms. Check the generic table in [../troubleshooting.md](../troubleshooting.md) first; the patterns behind these fixes are in [visual-editing-reference.md](visual-editing-reference.md).

Render errors don't reach the browser console by default: the error card fades and verbose logging is off. While debugging, pass `verbose: true` to the plugin (`addPlugin(editableRegions, { verbose: true })`), rebuild, and read the console inside the editor. Warnings from the config replay and from stubbed packages always print.

Install the latest `@cloudcannon/editable-regions`. **0.0.19 is the minimum**: it fixed `.html` includes as components, `process is not defined` in the bundle, async configs, and sites with large collections. On an older version, upgrade before debugging anything else.

## Build and bundle

| Symptom                                                                                               | Cause                                                                               | Fix                                                                                                                                              |
| ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Could not locate an Eleventy config file to auto-mirror helpers from`                                | The config isn't at a default path (`.eleventy.js`, `eleventy.config.{js,mjs,cjs}`) | Set `liquid.configPath` to it                                                                                                                    |
| The bundle builds, but loading it throws `Could not load the "sharp" module` and no component renders | `@11ty/eleventy-img` (or `sharp`) is bundled — it isn't stubbed automatically       | `liquid: { browserStub: ["@11ty/eleventy-img"] }` → [The config runs in the browser](visual-editing-reference.md#the-config-runs-in-the-browser) |

## In the editor

| Symptom                                                                                                                                                                                                             | Cause                                                                                                                                                           | Fix                                                                                                                                                                                               |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Console: `Replaying the Eleventy config to mirror its helpers threw: …`, and some filters are unknown in the editor                                                                                                 | A call outside `addPlugin` threw during the replay, so every helper registered after it is missing — often a plugin factory called as `addPlugin(factory({…}))` | Stub the package that threw, or give the lost helpers browser overrides → [The config runs in the browser](visual-editing-reference.md#the-config-runs-in-the-browser)                            |
| `Failed to find included template "<name>"`                                                                                                                                                                         | `data-component` isn't the include path — a bare name (`hero` for `components/hero`), or an `.html` include named without `.html`                               | Use the path relative to the includes directory → [Component names are include paths](visual-editing-reference.md#component-names-are-include-paths)                                              |
| An `.html` include fails as a component with a Liquid parse error                                                                                                                                                   | The site sets `htmlTemplateEngine: "njk"`, so the include is Nunjucks, but the plugin bundles every `.html` file as Liquid                                      | Only `.liquid` includes can be components on that site → [overview.md § Which path the site takes](overview.md#which-path-the-site-takes)                                                         |
| Markdown shows raw in a re-rendered component                                                                                                                                                                       | The site's markdown filter is named `renderContent`, which the plugin reserves, or the include uses the Render plugin's `renderContent: "md"`                   | Rename the filter (`renderMarkdown`) and update its callers → [Text regions and markdown in Eleventy](visual-editing-reference.md#text-regions-and-markdown-in-eleventy)                          |
| A custom filter or shortcode behaves differently in the editor, with no warning                                                                                                                                     | It has a [reserved name](visual-editing-reference.md#reserved-names), so the plugin's own version runs                                                          | Rename it                                                                                                                                                                                         |
| `"<package>" was called in the browser live-editing bundle`                                                                                                                                                         | A stubbed package was called while rendering — usually an image shortcode                                                                                       | Guard the call with `ENV_CLIENT`, or give the helper a browser override → [`ENV_CLIENT` in Eleventy](visual-editing-reference.md#env_client-in-eleventy)                                          |
| A component renders in the build but is blank, or missing values, in the editor                                                                                                                                     | The include reads a variable from its parent's scope (a loop variable, a page variable, an `assign`), which the build sees and the editor doesn't               | Pass the value in the `data-prop` object → [The include's data is the `data-prop` value](visual-editing-reference.md#the-includes-data-is-the-data-prop-value)                                    |
| A component renders nothing at build time or in the editor, with no error                                                                                                                                           | `includeWith` got an inline object, extra arguments, or a value that isn't an object                                                                            | Pass one object variable → [The include's data is the `data-prop` value](visual-editing-reference.md#the-includes-data-is-the-data-prop-value)                                                    |
| A header or footer re-renders empty, or with old values, after an edit                                                                                                                                              | The include reads `_data` by name, which the editor's engine doesn't have                                                                                       | Bind the data file as the region's `data-prop` → [Data files and `@data`](visual-editing-reference.md#data-files-and-data)                                                                        |
| A filter returns nothing in the editor                                                                                                                                                                              | It reads the data cascade (`this.context.environments`), which is empty there, or it's an arrow function reading `this`                                         | Pass the value as an argument; use `function` → [The config runs in the browser](visual-editing-reference.md#the-config-runs-in-the-browser)                                                      |
| An error card names a path from a layout, `eleventyComputed` or JS data                                                                                                                                             | The value isn't in the edited file                                                                                                                              | Remove the region → [Data paths in Eleventy](visual-editing-reference.md#data-paths-in-eleventy)                                                                                                  |
| An empty array has nowhere to add a first item                                                                                                                                                                      | The container is guarded with `size > 0`, `!= empty` or `\| length`                                                                                             | Guard on presence (`{% if items %}`), or `{% if items or ENV_CLIENT %}` inside an include → [`ENV_CLIENT` in Eleventy](visual-editing-reference.md#env_client-in-eleventy)                        |
| Nunjucks: after reordering two blocks of the same type, one block shows the other's markup, or an edit saves into the wrong block                                                                                   | Template-array items with the same `data-id` reuse each other's DOM outside regions                                                                             | Make every visible part a region, and remove `{% if %}` around optional parts → [Nunjucks sites](visual-editing-reference.md#nunjucks-sites)                                                      |
| Nunjucks: a new block appears in the sidebar, but the page shows an error card "Failed to render array item … no child with a matching 'data-id' value … and no 'data-component' or 'data-component-key' attribute" | No `<template data-id>` blueprint matches the new item's `data-id` — unique ids per item, or a block type with no blueprint                                     | One blueprint per block type, with type ids → [Nunjucks sites](visual-editing-reference.md#nunjucks-sites). Don't add the `data-component` the card suggests: Nunjucks has no component re-render |
